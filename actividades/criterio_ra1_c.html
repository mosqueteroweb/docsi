1. Test de Autoevaluación

Responde las 5 preguntas. La solución correcta y su justificación aparecen al final de la sección.

1

El POST (Power-On Self Test) se ejecuta:

  • a)Dentro del sistema operativo
  • b)En la memoria virtual
  • c)Por la BIOS/UEFI al encender, antes del SO
  • d)Solo al apagar el equipo
2

Si al arrancar suena un pitido largo y continuo, normalmente indica:

  • a)Arranque correcto
  • b)Fallo de memoria RAM o tarjeta de vídeo
  • c)Conexión de red activa
  • d)Actualización de BIOS exitosa
3

El gestor de arranque (bootloader) se encarga de:

  • a)Apagar la fuente
  • b)Cargar el núcleo del sistema operativo en memoria
  • c)Formatear el disco
  • d)Detectar la RAM
4

¿Qué orden de arranque (boot order) es lógico para instalar un SO desde USB?

  • a)Disco duro → Red → USB
  • b)USB → Disco duro → Red
  • c)Red → USB → Disco
  • d)Solo disco duro
5

El Secure Boot impide:

  • a)El acceso a Internet
  • b)El arranque de sistemas no firmados digitalmente
  • c)El uso de la RAM
  • d)La instalación de la CPU

Soluciones del test

  1. C) — El POST es la autocomprobación inicial de hardware antes de cargar el SO.
  2. B) — Los códigos de pitidos señalan fallos de hardware como la RAM.
  3. B) — Tras el POST, el bootloader carga el kernel del SO.
  4. B) — El USB debe tener prioridad para iniciar el medio de instalación.
  5. B) — Secure Boot solo permite arrancar cargadores firmados.

2. Ejemplo Resuelto NO EVALUABLE

Caso práctico resuelto paso a paso para autoaprendizaje.

Verificación de la puesta en marcha de un equipo

Un técnico enciende un PC recién montado. Describe paso a paso cómo verificar que la puesta en marcha es correcta.

Resolución paso a paso
1
1. Alimentación: pulsar el botón de encendido y comprobar que la fuente arranca (ventiladores girando, LED de encendido).
2
2. POST: la BIOS/UEFI realiza la autocomprobación; deben verse los mensajes en pantalla sin pitidos de error.
3
3. Detección de hardware: entrar en la BIOS (Supr/F2) y verificar que CPU, RAM y disco aparecen con sus capacidades.
4
4. Orden de arranque: confirmar que el dispositivo deseado (disco/USB) está en primer lugar.
5
5. Carga del SO: el bootloader carga el núcleo y el sistema operativo inicia sesión correctamente.
Conclusión: Si no hay pitidos de error, el hardware se detecta en la BIOS y el SO carga, la puesta en marcha es correcta. Cualquier fallo (pitido, pantalla negra, disco no detectado) se aisla en la fase correspondiente.

Segundo caso — Caso 2 — Arranque dual

Un equipo tiene Windows y Linux. El gestor de arranque (GRUB) permite elegir. Pasos: al encender, el firmware carga GRUB, que lista los SO y arranca el elegido. Conclusión: el proceso de puesta en marcha depende del gestor y del firmware (BIOS/UEFI).
