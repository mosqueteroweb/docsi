Criterio RA3-f: Realizar y restaurar copias de seguridad

RA3-f

Se evalúa la capacidad de planificar, ejecutar y verificar la restauración de copias de seguridad con rsync, dd y herramientas de imagen o nube.

Test de conocimientos

¿Qué herramienta sincroniza archivos copiando solo los cambios?

  • dd
  • rsync
  • mkfs
  • grep

Solución: b.

Para clonar un disco entero byte a byte se usa:

  • rsync
  • tar
  • dd
  • find

Solución: c.

La regla 3-2-1 de backups indica:

  • 3 copias, 2 medios, 1 externa
  • 3 discos, 2 CPU, 1 red
  • 3 usuarios, 2 claves, 1 admin
  • 3 días, 2 horas, 1 minuto

Solución: a.

Una copia incremental:

  • Copia todo siempre
  • Solo copia los cambios desde la última copia
  • Borra el original
  • Comprime la RAM

Solución: b.

¿Por qué es importante verificar la restauración?

  • Para gastar menos disco
  • Para asegurar que la copia es válida
  • Para cifrarla
  • Para acelerar el SO

Solución: b.

Ejemplo resuelto (no evaluable)

Situación: quieres una copia de seguridad diaria de /home en un disco externo.

Solución: con rsync haces una copia espejo que conserva permisos:

rsync -avh --delete /home/ /mnt/backup/home/

Para restaurar, inviertes el origen y destino: rsync -avh /mnt/backup/home/ /home/. Verificas comparando el número de archivos con find /home | wc -l.

Actividad evaluable

Diseña una estrategia de copias de seguridad (mínimo 100 palabras) para un pequeño despacho con un servidor Linux. Indica: tipo de copia (completa/incremental), frecuencia, herramienta (rsync o dd) y dónde guardarlas (medio y ubicación) aplicando la regla 3-2-1. Incluye el comando concreto que usarías para la copia y cómo comprobarías que la restauración funciona.
