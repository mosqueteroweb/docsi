Evolución histórica y clasificación de los sistemas operativos

El sistema operativo (SO) es el software que gestiona los recursos hardware y ofrece una interfaz a las aplicaciones y al usuario. Su evolución pasó de los monitores residentes de los años 50, pasando por los sistemas de lote (batch), el tiempo compartido (multitarea), hasta los SO modernos gráficos y multiusuario.

1. Hitos históricos

  • 1950s: operación con tarjetas perforadas y monitores residentes sin SO como tal.
  • 1960s: tiempo compartido (CTSS, MULTICS) y aparece UNIX.
  • 1980s: SO con interfaz gráfica (Mac OS, Windows) y auge de MS-DOS.
  • 1990s: Linux y el software libre; Windows NT para servidores.
  • 2000s–hoy: virtualización, cloud, móviles (Android/iOS) y contenedores.

3. Arquitectura básica

Un SO se apoya en el núcleo (kernel) que gestiona CPU, memoria y dispositivos, y en espacio de usuario donde corren las aplicaciones. Los modelos varían entre monolítico (Linux, Windows) y microkernel (Mach, MINIX).

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • El SO es el "capataz" del hardware. Sin él, cada programa tendría que hablar directo con el disco, la pantalla y la red. El SO centraliza esa gestión para que las aplicaciones sean fáciles de escribir.
  • Monotarea/multitarea y mono/multiusuario son ejes distintos. Un SO puede ser multitarea pero monousuario (una sola persona, muchos programas), o multiusuario y multitarea a la vez. No son lo mismo.
  • Kernel vs aplicación: dos "pisos". El núcleo (kernel) tiene privilegios totales y habla con el hardware; las apps viven en "espacio de usuario" y piden favores al kernel. Ese muro protege el sistema.

Para profundizar en los contenidos actuales

De lote a tiempo compartido. Al principio se metía un trabajo, se esperaba, y otro (batch). El tiempo compartido (CTSS, MULTICS) reparte el tiempo de CPU entre varios usuarios tan rápido que parece simultáneo: así nace la multitarea y el concepto de "sesión".

UNIX y su herencia. UNIX (años 60) fijó ideas que perduran: "todo es un archivo", tuberías (pipes) para encadenar comandos, multiusuario con permisos. Linux, macOS e iOS descienden de esa filosofía; incluso Windows adoptó conceptos similares.

CLI vs GUI. La interfaz de texto (línea de comandos) es potente y scripteable; la gráfica (GUI) es accesible. Un mismo SO suele ofrecer ambas (Linux tiene bash y entorno gráfico; Windows tiene PowerShell y escritorio).

Monolítico vs microkernel. En el monolítico (Linux, Windows) todo el núcleo corre en modo privilegiado: rápido pero un fallo lo tumba todo. En el microkernel (Mach, MINIX) solo lo mínimo está en el núcleo y el resto son servicios en espacio de usuario: más seguro y modular, algo más lento. Es el compromiso rendimiento vs robustez.

SO moderno: virtualización y contenedores. Hoy el SO anfitrión (host) ejecuta máquinas virtuales o contenedores (Docker), permitiendo aislar aplicaciones y aprovechar mejor el hardware. Es la base de la nube.

Revisión didáctica

  • Multitarea ≠ multiusuario. Multitarea = varios programas a la vez; multiusuario = varias personas a la vez. Un SO puede tener una sin la otra.
  • Kernel no es "el SO entero". Es su núcleo; encima corren servicios y aplicaciones. Decir "el kernel es el SO" es reduccionista.
  • Linux no es "un SO de los 90 olvidado". Es la base de la mayoría de servidores, Android y la nube actual.
  • Monolítico no es "peor". Es un diseño distinto; Linux es monolítico y compite en rendimiento con los microkernel.
  • CLI sigue existiendo. No es "lo de antes"; administradores y scripts lo usan a diario.

Hilo de aprendizaje sugerido: (1) ¿qué es un SO y para qué? → (2) evolución (lote→tiempo compartido→GUI→libre→cloud) → (3) clasificar (tarea/usuario/interfaz) → (4) arquitectura (kernel/espacio usuario; monolítico/microkernel) → (5) SO actuales y virtualización.
