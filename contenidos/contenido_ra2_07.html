Gestores de arranque. Configuración y reparación

El gestor de arranque (bootloader) es el primer software que se ejecuta tras el firmware; carga el núcleo del SO en memoria y le pasa el control. Su configuración es clave en sistemas multiarranque (varios SO).

1. Firmware: BIOS vs UEFI

AspectoBIOS (legado)UEFI (moderno)

2. Bootloaders comunes

  • GRUB2: gestor multiarranque en Linux, configurable vía /etc/default/grub.
  • Windows Boot Manager: gestor nativo de Windows.
  • systemd-boot: ligero para UEFI en distros modernas.

3. Configuración y reparación

En GRUB se edita el archivo de configuración y se regenera con update-grub. Si el arranque falla, se usa un Live USB para reparar el gestor (p.ej. grub-install / boot-repair) o restaurar el registro de arranque de Windows con bootrec /fixboot.

4. Caso práctico de reparación

Un PC con Windows y Linux deja de arrancar Linux tras reinstalar Windows (este sobreescribe el MBR/EFI). Se arranca con un Live USB de Linux y se reejecuta grub-install para restaurar GRUB como gestor principal.

Ejemplo resuelto en clase

Caso práctico: Reparar el gestor de arranque (Linux).

  1. Arranca un live USB y entra en la terminal.
  2. Monta la partición raíz: mount /dev/sda1 /mnt.
  3. Reinstala GRUB: grub-install --root-directory=/mnt /dev/sda.
  4. Reinicia y comprueba que el menú de arranque aparece.

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • El arranque es una "escalera" de varios peldaños. Firmware (BIOS/UEFI) → bootloader → núcleo → SO. Cada peldaño entrega el testigo al siguiente; si uno falla, no subes.
  • El bootloader es el "portero" del arranque. Sabe dónde está el núcleo en el disco y cómo cargarlo; en multiarranque, además, te deja elegir qué SO levantar.
  • BIOS/UEFI no es opcional según gusto. El firmware es lo que trae la placa; marca si usas MBR o GPT y si puedes usar Secure Boot.

Para profundizar en los contenidos actuales

BIOS vs UEFI en la práctica. BIOS arranca en modo real de 16 bits y busca el sector de arranque en MBR; frágil y limitado a 2 TB. UEFI lee un "EFI System Partition" (FAT32) con los bootloaders como archivos, soporta GPT, discos grandes y Secure Boot (firma criptográfica).

GRUB2 y Windows Boot Manager. GRUB2 (Linux) es muy configurable y soporta múltiples SO; el Boot Manager de Windows es el de Microsoft. En dual boot, GRUB suele instalarse en la EFI y encadena o da entrada a Windows.

Por qué Windows "rompe" Linux. Al reinstalar Windows, este escribe su propio gestor en la EFI y oculta/sustituye a GRUB. Por eso Linux deja de aparecer; se repara desde Live USB con grub-install y update-grub.

Secure Boot y sus molestias. Bloquea cargadores no firmados; algunos Linux antiguos o drivers propietarios (NVIDIA) daban problemas. Hoy distros principales lo soportan; si no, se desactiva en UEFI (bajando algo la seguridad).

Live USB como cuchara de rescate. Un USB con Linux "en vivo" arranca sin tocar el disco instalado; permite reparar arranque, recuperar archivos o cambiar contraseñas. Es la herramienta básica de soporte.

Revisión didáctica

  • Bootloader no es el firmware. BIOS/UEFI es el firmware (placa); GRUB/BootMgr es el bootloader (disco). Dos peldaños distintos.
  • Reinstalar Windows no "borra Linux". Sobrescribe el gestor de arranque; los datos de Linux siguen en su partición. Se repara, no se reinstala.
  • UEFI con MBR es combinación problemática. Lo natural es UEFI+GPT; forzar MBR con UEFI da líos de arranque.
  • Secure Boot no es "antivirus". Solo verifica la firma del cargador en el arranque; no protege mientras usas el SO.
  • Live USB arranca "fuera" del disco. No confundir con instalar; es un SO temporal en memoria/USB para rescate.

Hilo de aprendizaje sugerido: (1) la escalera firmware→bootloader→núcleo→SO → (2) BIOS vs UEFI (MBR/GPT, Secure Boot) → (3) GRUB2 y Boot Manager → (4) multiarranque y por qué Windows pisa GRUB → (5) reparación con Live USB → (6) Secure Boot y sus implicaciones.
