Tecnologías de virtualización. Tipos.

La virtualización permite ejecutar varios sistemas operativos (invitados) sobre uno físico (anfitrión) mediante una capa de abstracción. Es clave en servidores, laboratorios de clase y cloud.

1. Tipos según la capa

  • Virtualización completa: el hipervisor emula todo el hardware (más compatible, algo más lento).
  • Paravirtualización: el SO invitado conoce que está virtualizado y colabora (más rendimiento, ej. Xen).
  • Contenedores: aislan procesos compartiendo el núcleo (Docker, LXC); más ligeros que las MV.
  • Emulación: imita una arquitectura distinta (QEMU).

2. Hipervisores

TipoDescripciónEjemplo
Tipo 1 (bare-metal)Corre sobre el hardware directoVMware ESXi, Hyper-V, KVM

3. Componentes

  • Máquina virtual (MV): sistema invitado con CPU/RAM/disco virtuales.
  • Snapshot: captura de estado para restaurar.
  • Migración en vivo: mover MV entre anfitriones sin parar.

4. Caso práctico

En clase se usa VirtualBox para que cada alumno instale Windows y Linux en MV sobre su equipo, sin tocar el SO real, pudiendo hacer snapshots antes de configurar red.

Ejemplo resuelto en clase

Caso práctico: Crear una MV con virtualización.

  1. Abre VirtualBox y pulsa 'Nueva'; asigna 2 GB RAM y 20 GB disco (virtual).
  2. Selecciona el tipo de virtualización: el anfitrión (host) comparte CPU/RAM con el invitado.
  3. Arranca la MV e instala el SO invitado como si fuera hardware real.
  4. Instala las Guest Additions para integración (carpetas compartidas, resolución).

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • Virtualizar = poner un "ordenador dentro del ordenador". El equipo físico (anfitrión) simula varios equipos virtuales (invitados) que creen tener su propio hardware.
  • El hipervisor es el "conserje". Reparte CPU, RAM y disco real entre las máquinas virtuales y evita que se pisen. Sin él, las MV no sabrían compartir.
  • MV vs contenedor: mismo objetivo, distinto nivel. La MV virtualiza hasta el hardware (con su SO propio); el contenedor solo aísla procesos compartiendo el mismo núcleo. Por eso los contenedores son más ligeros.

Para profundizar en los contenidos actuales

Tipo 1 vs Tipo 2. El hipervisor Tipo 1 (ESXi, Hyper-V, KVM) corre directo sobre el hardware: máximo rendimiento, típico en servidores. El Tipo 2 (VirtualBox, VMware Workstation) corre como programa sobre un SO normal: cómodo para clase, pero con una capa más.

Virtualización completa vs paravirtualización. En la completa, el hipervisor imita el hardware y el SO invitado no se entera (compatible con cualquiera). En la paravirtualizada, el SO invitado "colabora" usando controladores especiales (virtio): más rápido, pero necesita soporte en el SO.

Contenedores (Docker/LXC). No arrancan un SO completo: aísalan una aplicación y sus librerías compartiendo el núcleo del anfitrión. Arrancan en segundos y gastan poco; por eso dominan la nube y los microservicios.

Emulación (QEMU). Imita una arquitectura distinta (ej. ejecutar ARM en x86). Es muy flexible pero lento, porque traduce cada instrucción. Útil para desarrollo de firmware o sistemas embebidos.

Por qué importa en clase y en la nube. En el aula, una MV permite a cada alumno instalar Windows/Linux "dentro" de su equipo sin romper nada, con snapshots para volver atrás. En la nube, la virtualización es la base de todo (IaaS).

Revisión didáctica

  • MV ≠ contenedor. La MV lleva su propio SO y núcleo virtual; el contenedor comparte núcleo y solo aísla la app. No son intercambiables.
  • Hipervisor Tipo 1 no es "mejor siempre". Es más eficiente en servidor, pero para uso de escritorio el Tipo 2 (VirtualBox) es más práctico.
  • Paravirtualización no es "virtualización a medias". Es una técnica de rendimiento que exige que el SO invitado colabore; no es peor, es distinta.
  • Emulación no es "lo mismo que virtualizar". Virtualizar corre código nativo; emular traduce arquitectura. La emulación es más lenta.
  • Snapshot no es copia de seguridad. El snapshot guarda el estado de la MV en un momento; si se corrompe el disco base, el snapshot también se pierde. Para respaldo real hay que exportar la MV.
