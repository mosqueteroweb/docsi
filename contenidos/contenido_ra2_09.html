Consideraciones previas a la instalación de SO libres y propietarios

Antes de instalar hay que evaluar requisitos y compatibilidad para evitar fallos y costes.

1. Requisitos hardware

  • CPU compatible (x86_64), RAM mínima (4 GB para SO actuales), disco con espacio y firmware (UEFI/BIOS).
  • Drivers: verificar que el fabricante ofrece soporte para el SO elegido.

2. Libre vs propietario

Ejemplo resuelto en clase

Caso práctico: Checklist previa a instalar SO.

  1. Verifica arquitectura (32/64 bits) compatible con el equipo.
  2. Confirma espacio en disco y RAM suficientes.
  3. Decide tipo de instalación: limpia vs actualización.
  4. Asegura copia de seguridad de datos y claves de licencia.

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • Antes de instalar = "leer el manual antes de montar el mueble". Comprobar que las piezas (HW) encajan con el SO evita sorpresas a mitad.
  • Compatibilidad no es "que arranque", es "que funcione". Un SO puede instalarase pero faltarle drivers (sin wifi, sin vídeo); por eso se verifica soporte antes.
  • Libre vs propietario afecta la "logística". Linux se baja gratis; Windows exige licencia y activación. Eso cambia el plan de aula (coste, claves, activación).

Para profundizar en los contenidos actuales

Inventario de hardware. Anotar CPU (¿x86_64?), RAM, disco libre y firmware. Si es UEFI, el disco debe ir con GPT; si BIOS, con MBR. Errar aquí bloquea el arranque.

Drivers y soporte. Windows suele traer drivers de fábrica o el fabricante los da; Linux los incluye en el núcleo (la "comunidad"), aunque algún componente propietario (wifi, NVIDIA) requiere pasos extra. Verificar antes ahorra líos.

Coste y licenciamiento. Linux es gratuito y se puede clonar en todos los puestos; Windows necesita licencias (OEM/retail/suscripción) y activación. En un centro, eso se planifica con el departamento.

Copia de seguridad previa. Antes de tocar particiones, respaldar datos y, si hay sistema, hacer una imagen. En el aula se hace una imagen "maestra" ya configurada para clonar el resto.

Planificación del particionado. Decidir tamaños: una partición para el SO, otra para datos (para que al reinstalar no se pierdan), y en dual boot, dejar espacio para el segundo SO.

Revisión didáctica

  • "Arranca" ≠ "funciona". Falta de drivers deja el equipo medio ciego (sin red, sin gráficos). La compatibilidad es sobre el funcionamiento completo.
  • GPT no es "mejor MBR por arte mágico". Depende del firmware: UEFI usa GPT; forzar MBR con UEFI da problemas.
  • Linux gratis no significa "sin plan". Igual necesita particiones, drivers específicos y, en empresa, soporte de pago (Red Hat).
  • Imagen ≠ copia de datos. La imagen clona el sistema; los datos de usuario van aparte si quieres preservarlos al reinstalar.
  • Licencia OEM no es transferible igual que retail. La OEM va ligada al equipo; eso condiciona el plan de renovación.

Hilo de aprendizaje sugerido: (1) inventariar HW (CPU/RAM/disco/firmware) → (2) verificar drivers/soporte → (3) libre vs propietario (coste, licencia) → (4) copia de seguridad + imagen maestra → (5) planificar particiones (SO/datos/dual) → (6) ejecutar la instalación con el plan listo.
