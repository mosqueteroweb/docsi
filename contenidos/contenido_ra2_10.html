Instalación de sistemas operativos libres y propietarios. Requisitos, versiones y licencias.

El proceso de instalación es similar en ambos mundos, pero difiere en herramientas, licencias y post-instalación.

1. GNU/Linux (libre)

  1. Descargar ISO de la distro (Ubuntu, Debian…).
  2. Grabar en USB booteable (Rufus/BalenaEtcher).
  3. Arrancar, particionar (GPT) y seguir el asistente.
  4. Instalar drivers/paquetes vía gestor (apt, dnf).
  5. Actualizar y crear usuario.

2. Microsoft Windows (propietario)

  1. Disponer de licencia/clave válida.
  2. Crear medio con Media Creation Tool.
  3. Instalar, activar con la clave, instalar drivers del fabricante.
  4. Aplicar Windows Update.

Ejemplo resuelto en clase

Caso práctico: Instalar un SO (ejemplo Windows/Linux).

  1. Arranca desde el medio y elige 'Instalar ahora'.
  2. Selecciona el disco/partición y formato (NTFS/ext4).
  3. Introduce la licencia (o prueba de 30 días) y crea el usuario.
  4. Tras reiniciar, instala controladores y actualizaciones.

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • Libre y propietario comparten el "esqueleto" de instalación. ISO → USB → arranque → particionar → copiar → configurar. Lo que cambia son las herramientas y el paso de licencia.
  • La licencia es el paso que solo aparece en el propietario. Linux pregunta "¿usuario?"; Windows pregunta "¿clave?". Esa es la gran diferencia práctica.
  • Gestor de paquetes vs Windows Update. Linux instala software y actualizaciones con un comando (apt/dnf); Windows lo hace con Windows Update y ejecutables. Distinto modelo de "mantener el SO".

Para profundizar en los contenidos actuales

Linux: el gestor de paquetes es la clave. Tras instalar, todo (drivers incluidos en el núcleo, navegador, editor) se añade con apt install o dnf. Las actualizaciones son archivos firmados del repositorio; por eso Linux rara vez necesita "buscar el driver en la web del fabricante".

Windows: licencia y activación. Necesitas una clave válida (OEM/retail/suscripción). La Media Creation Tool crea el USB oficial. Tras instalar, activas con la clave y aplicas Windows Update (drivers + seguridad). Los drivers propietarios suelen bajarse del fabricante.

Versiones y ediciones. Ubuntu tiene LTS (soporte largo, ideal aula) y versiones normales; Windows separa Home/Pro/Enterprise y Server. Elegir la edición correcta evita líos de funciones (ej. Active Directory solo en Pro/Server).

Requisitos reales vs mínimos. Los mínimos oficiales (4 GB RAM) dan un SO lento; para uso aula conviene el doble. El disco: 25 GB de Ubuntu es justo; dejar margen para actualizaciones.

Post-instalación distinta. En Linux, añadir software y usuario es inmediato vía gestor. En Windows, activar, instalar drivers del fabricante y luego el software de aula. Planificar esto ahorra tiempo en un centro.

Revisión didáctica

  • ISO no es "el SO ya instalado". Es la imagen de instalación; hay que volcarla al disco. Error típico creer que basta copiarla.
  • La clave de Windows no es "opcional". Sin activación, el SO funciona limitado y con marca de agua. En aula se gestiona centralizadamente.
  • apt no es "una tienda cualquiera". Instala paquetes del sistema y resuelve dependencias; no confundir con un instalador de .exe suelto.
  • LTS no es "versión vieja peor". Es la de soporte largo, la recomendada para producción/aula por estabilidad.
  • Los requisitos mínimos no son "recomendados". Cumplirlos apenas arranca; para uso real conviene superarlos.

Hilo de aprendizaje sugerido: (1) esqueleto común de instalación → (2) Linux: ISO→apt, sin clave → (3) Windows: ISO→clave→Update, con licencia → (4) versiones/ediciones y cuándo usar cada una → (5) requisitos reales vs mínimos → (6) post-instalación en cada mundo.
