Instalación/desinstalación de aplicaciones. Requisitos, versiones y licencias.

Además del SO, hay que instalar el software de usuario. Cada SO tiene su método y gestor de paquetes.

1. En Linux

  • Gestor de paquetes: apt (Debian/Ubuntu), dnf (Fedora), pacman (Arch).
  • Comando: sudo apt install nombre. Desinstalar: apt remove.
  • Flatpak/Snap: paquetes universales entre distros.

2. En Windows

  • Instalador (MSI/EXE): asistente gráfico; o Winget por línea de comandos.
  • Desinstalar vía Configuración o winget uninstall.
  • Cuidado con barras/software no deseado en instaladores de terceros.

3. Requisitos y licencias de apps

Toda app tiene requisitos (SO, RAM, dependencias) y licencia (libre GPL, propietaria de pago, freemium). Verificar compatibilidad antes de instalar.

Ejemplo resuelto en clase

Caso práctico: Instalar y desinstalar una app.

  1. Abre el gestor de paquetes (Linux: apt install gimp; Windows: asistente).
  2. Acepta la licencia y elige ruta de instalación.
  3. Verifica que el acceso directo aparece en el menú.
  4. Desinstala desde 'Agregar o quitar programas' y confirma que libera espacio.

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • Instalar una app es "añadir una herramienta al cajón". El SO ya está; la app es software de usuario que se suma. El método depende del SO.
  • Repositorio vs web del fabricante. Linux baja apps de un repositorio central (verificado, con dependencias); Windows suele bajar un .exe de la web. Distinto grado de control y seguridad.
  • Desinstalar no es "borrar el icono". Hay que quitar los archivos y registros; si no, quedan rastros y archivos sueltos.

Para profundizar en los contenidos actuales

Gestor de paquetes en Linux. apt (Debian/Ubuntu), dnf (Fedora), pacman (Arch) resuelven dependencias solos: si LibreOffice necesita una librería, la bajan. Eso evita el "infierno de DLL" de Windows.

Flatpak y Snap. Son formatos universales que empaquetan la app y sus dependencias, funcionando en cualquier distro. Útiles cuando la app no está en el repositorio oficial. A cambio, ocupan más.

Windows: EXE/MSI y Winget. El instalador gráfico (siguiente-siguiente) es cómodo pero propenso a barras (bloatware). Winget es la alternativa por línea de comandos, ideal para automatizar en aulas.

Licencia de la app. Igual que el SO: GPL (libre), pago (clave), freemium. Verificar compatibilidad (¿la app corre en mi SO/versión?) antes de instalar evita desperdicio.

Dependencias y entornos. Una app puede requerir runtime (Java, .NET, Python). Si falta, no arranca. Por eso el gestor de paquetes, al instalar, se encarga de traerlo; en Windows a veces toca instalarlo aparte.

Revisión didáctica

  • Borrar el acceso directo ≠ desinstalar. El programa sigue en disco. Hay que usar el gestor (apt remove) o "Agregar/Quitar programas" de Windows.
  • apt no es "la única forma en Linux". También Flatpak/Snap y, en casos, compilar desde código fuente. No reducir a un solo método.
  • Winget no es "igual que hacer doble clic en el .exe". Es gestor por línea de comandos que ayuda a automatizar; el .exe es el instalador manual.
  • "Siguiente-siguiente" puede instalar barras. Los instaladores de terceros meten software no deseado si no se desmarca. Ojo en el aula.
  • Dependencia no resuelta = app no arranca. Si falta el runtime, el error es críptico; hay que identificar qué falta.

Hilo de aprendizaje sugerido: (1) app = software de usuario sobre el SO → (2) Linux: gestor de paquetes (apt/dnf) y dependencias automáticas → (3) Flatpak/Snap universales → (4) Windows: EXE/MSI vs Winget → (5) licencia y compatibilidad → (6) desinstalación correcta y por qué importa.
