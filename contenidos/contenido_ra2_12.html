Actualización y recuperación de sistemas operativos y aplicaciones

Mantener el SO y las apps actualizados es clave para seguridad y estabilidad; disponer de un plan de recuperación evita pérdidas ante fallos.

1. Actualizaciones

  • Linux: apt update && apt upgrade; actualizaciones del núcleo y paquetes.
  • Windows: Windows Update (acumulativos, drivers, características).
  • Apps: gestores de paquetes y tiendas (Microsoft Store, Snapcraft).

2. Recuperación ante fallos

  • Punto de restauración: (Windows) revierte configuración del sistema.
  • Live USB: arranca un SO desde memoria para reparar el instalado.
  • Copias de seguridad: imagen del sistema o archivos (véase RA3).
  • Modo seguro / recovery: arranque mínimo para diagnosticar.

3. Política de mantenimiento

Programar actualizaciones automáticas en horario de bajo uso, verificar copias de seguridad y documentar incidentes (véase contenido 13).

Ejemplo resuelto en clase

Caso práctico: Actualizar y recuperar el SO.

  1. Abre 'Windows Update' / apt upgrade y aplica parches.
  2. Crea un punto de restauración antes de cambios mayores.
  3. Si falla el arranque, usa el medio de recuperación y 'Reparar inicio'.
  4. Restaura desde copia de seguridad de sistema si es necesario.

Ejercicio para resolver (que propone el profesor al alumno): El alumno aplica actualizaciones y demuestra cómo crear/restaurar un punto de restauración.

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • Actualizar = "poner parches al coche mientras rueda". Se corrigen fallos de seguridad y se mejoran cosas sin reinstalar. Ignorarlo es dejar el coche sin frenos nuevos.
  • Recuperar ≠ reinstalar. El plan de recuperación busca volver al estado bueno sin perder datos; reinstalar es el último recurso. Por eso existen puntos y copias.
  • El fallo puede ser "no arranca" o "arranca mal". Si no arranca, hace falta un medio externo (Live USB); si arranca, basta con restaurar dentro del SO.

Para profundizar en los contenidos actuales

Linux: apt update vs upgrade. update solo refresca la lista de paquetes disponibles; upgrade los instala. Hay que hacer ambos. Las actualizaciones del núcleo exigen reinicio para aplicarse.

Windows Update. Además de parches, trae actualizaciones acumulativas, de drivers y, a veces, nuevas características. Se puede pausar y programar; en aula se hace en horario de bajo uso para no interrumpir clase.

Punto de restauración (Windows). Guarda el estado de los archivos del sistema y el registro; al restaurar, revierte cambios recientes sin tocar tus documentos. No sustituye a la copia de seguridad de datos.

Live USB y modo recovery. Si el SO no arranca, el Live USB (Linux "en vivo") permite acceder al disco y reparar (p. ej. reinstalar GRUB). El modo recovery/seguro arranca con lo mínimo para diagnosticar.

Política de mantenimiento. Automatizar actualizaciones, verificar que las copias funcionan (restaurar una de prueba) y documentar incidentes. Un plan sin copias probadas es un plan que fallará el día menos pensado.

Revisión didáctica

  • "apt update" no actualiza nada. Solo actualiza la lista; falta upgrade. Error típico creer que con update basta.
  • Punto de restauración ≠ copia de datos. El punto no salva tus documentos; si el disco falla, se pierden. Hace falta copia aparte (RA3).
  • Live USB no es "reinstalar". Es rescate sin tocar el disco instalado; útil para reparar arranque o recuperar archivos.
  • Actualizar no es "opcional". Las actualizaciones cierran agujeros de seguridad; no ponerlas expone el equipo.
  • Programar no es "olvidarse". Hay que comprobar que las copias se restauraían; una copia nunca probada puede estar corrupta.

Hilo de aprendizaje sugerido: (1) por qué actualizar (seguridad) → (2) Linux: update+upgrade, reinicio por núcleo → (3) Windows Update y programación → (4) recuperación: punto vs Live USB vs copia → (5) modo seguro/recovery → (6) políca de mantenimiento y prueba de copias.
