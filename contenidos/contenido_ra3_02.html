Estructura jerárquica del sistema de archivos

Tanto los sistemas libres (GNU/Linux, *BSD) como los propietarios (Windows) organizan los archivos en una estructura de árbol de directorios. La diferencia principal es el punto de raíz y la forma de nombrar las unidades.

1. Árbol de directorios en GNU/Linux (FHS)

En Linux existe un único árbol cuyo directorio raíz es /. El estándar FHS (Filesystem Hierarchy Standard) define el significado de cada carpeta:

DirectorioContenido
/Raíz de todo el sistema.
/homeDirectorios personales de los usuarios.
/etcArchivos de configuración del sistema.
/varDatos variables (logs, colas).
/bin, /usrProgramas y binarios del sistema.
flowchart TD
    R["/ raíz"] --> ETC[/etc config]
    R --> HOME[/home]
    HOME --> U1[/home/usuario]
    HOME --> U2[/home/invitado]
    R --> VAR[/var logs]
    R --> USR[/usr binarios]
    R --> BOOT[/boot kernel]

2. Estructura en Windows

Windows no tiene una raíz única: cada partición o unidad recibe una letra (C:, D:). La carpeta de usuarios se encuentra en C:\\Users y los datos de programa en C:\\ProgramData y C:\\Program Files.

C:\
├── Users\
│   ├── usuario\
│   └── Invitado\
├── Program Files\
├── ProgramData\
└── Windows\
flowchart TD
    C["C:\\ unidad"] --> USERS["C:\\Users"]
    USERS --> U1["C:\\Users\\usuario"]
    USERS --> U2["C:\\Users\\Invitado"]
    C --> PF["C:\\Program Files"]
    C --> PD["C:\\ProgramData"]
    C --> WIN["C:\\Windows"]

3. Rutas absolutas y relativas

Una ruta absoluta indica la ubicación completa desde la raíz (ej. /home/usuario/docs/informe.txt o C:\\Users\\usuario\\docs\\informe.txt). Una ruta relativa parte del directorio actual (ej. docs/informe.txt).

  • . representa el directorio actual.
  • .. representa el directorio padre.
  • ~ en Linux representa el directorio personal del usuario.
# Linux: ruta absoluta vs relativa
cd /home/usuario/docs        # absoluta
cd ../descargas              # relativa (sube un nivel)
# Windows (PowerShell)
cd C:\Users\usuario\docs     # absoluta
cd ..\descargas              # relativa

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • El árbol de directorios es "el callejero del disco". Cada carpeta es una dirección; sin esa jerarquía, buscar un archivo sería como encontrar una casa sin calles.
  • Linux: un solo árbol; Windows: un bosque por letra. En Linux todo cuelga de /; en Windows cada disco es C:, D:. Es la diferencia de "raíz única" vs "unidades".
  • Ruta absoluta vs relativa = dirección completa vs "desde aquí". La absoluta no depende de dónde estás; la relativa sí. Por eso un script con rutas relativas puede fallar según desde dónde se ejecute.

Para profundizar en los contenidos actuales

FHS en Linux. El estándar define qué va en cada carpeta: /etc (configuración), /var (datos variables como logs), /home (usuarios), /usr (programas), /boot (kernel). Saberlo ayuda a localizar cosas y a no meter la pata borrando lo del sistema.

Windows: Users, Program Files, ProgramData. Los programas van en C:\Program Files (y ProgramData para datos comunes); los usuarios en C:\Users. A diferencia de Linux, aquí los datos de programa y del usuario están separados por diseño.

Rutas relativas y el directorio actual (cwd). . es "aquí", .. es "el padre", ~ es el home. Un comando como cp ../docs/a.txt . copia desde el padre a la carpeta actual. Si no sabes dónde estás (pwd), la relativa te confunde.

Por qué importa en administración. Los scripts de copia de seguridad, las políticas y los accesos remotos usan rutas. Una ruta mal escrita (barra invertida en Linux, o absoluta cuando querías relativa) rompe la tarea.

Permisos y estructura van de la mano. En Linux, /home/usuario solo lo lee ese usuario; en Windows, C:\Users\usuario igual. La estructura refleja el control de acceso.

Revisión didáctica

  • Linux no tiene "discos con letra". Todo está bajo /; un USB se monta en un punto (ej. /mnt/usb), no aparece como D:.
  • "/" en Windows no es la raíz. En Windows la raíz es C:\ (con barra invertida); / en Linux es distinto y usa barra normal.
  • Ruta relativa no es "más corta por arte mágico". Depende del directorio actual; cambiar de carpeta cambia a dónde apunta. Usarla sin saber dónde estás da errores.
  • ~ no es "cualquier home". Es el home del usuario que ejecuta; en scripts multiusuario, confundirlo es un fallo de seguridad.
  • Borrar /etc no es "borrar una carpeta más". Es la configuración del sistema; en Linux eso deja el equipo inutilizable. La estructura importa.

Hilo de aprendizaje sugerido: (1) árbol como callejero → (2) Linux: raíz única y FHS (/etc, /var, /home) → (3) Windows: letras y Users/Program Files → (4) rutas absolutas vs relativas (., .., ~) → (5) por qué importa en scripts/admin → (6) estructura y permisos van juntos.
