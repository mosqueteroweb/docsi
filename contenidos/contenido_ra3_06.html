Particiones, volúmenes y mantenimiento de discos

Administrar discos implica crear particiones (divisiones lógicas del disco), gestionar volúmenes (con LVM), desfragmentar, chequear errores y cifrar datos. Cada sistema ofrece herramientas de línea de comandos y gráficas.

1. Particionado: fdisk y gparted

fdisk es la herramienta clásica de particionado en Linux (MBR); gparted es su equivalente gráfico. En Windows se usa el Administrador de discos.

# Listar tablas de particiones
sudo fdisk -l
# Iniciar particionado interactivo de /dev/sdb
sudo fdisk /dev/sdb
# Redimensionar con la herramienta gráfica
sudo gparted

2. Volúmenes lógicos: LVM y BitLocker

LVM (Logical Volume Manager) permite crear volúmenes lógicos redimensionables sobre particiones físicas. BitLocker (Windows) cifra toda la unidad para proteger los datos.

# Crear volumen físico, grupo y lógico
sudo pvcreate /dev/sdb1
sudo vgcreate vg_datos /dev/sdb1
sudo lvcreate -L 10G -n lv_home vg_datos
# Cifrar una unidad con BitLocker (PowerShell, admin)
Enable-BitLocker -MountPoint "D:" -EncryptionMethod AES256

    A[Disco físico] --> B[Partición]

3. Desfragmentación y chequeo

La desfragmentación reorganiza los datos en discos HDD para mejorar el acceso (NTFS). El chequeo (fsck en Linux, chkdsk en Windows) detecta y repara errores del sistema de archivos.

# Chequear y reparar (desmontado)
sudo fsck /dev/sdb1
# Windows: chequear disco C:
chkdsk C: /f
# Windows: desfragmentar
defrag C: /U

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • El disco es "una hoja en blanco"; la partición, "las líneas que la dividen". Sin particionar, el SO no sabe dónde escribir. La partición marca los límites lógicos.
  • Volumen lógico = "repintar el cuarto sin obra". Con LVM puedes agrandar/encoger una unidad sin borrar; con particiones fijas, no. Es flexibilidad sobre el hardware.
  • Cifrado = "la caja con candado". BitLocker hace ilegible el disco si se lo llevan; útil en portátiles de un centro.

Para profundizar en los contenidos actuales

fdisk vs gparted. fdisk es la CLI clásica para tablas MBR; para GPT se prefiere gdisk/parted. gparted es el frontal gráfico (más intuitivo pero igual de definitivo: borrar es borrar).

LVM: la pirámide PV→VG→LV. El volumen físico (PV) es la partición; el grupo (VG) las junta; el lógico (LV) es lo que ves como unidad. Así puedes redimensionar "en caliente" y añadir discos sin reinstalar.

Desfragmentación: HDD sí, SSD no. En discos mecánicos, los archivos se fragmentan y la desfragmentación acelera el acceso. En SSD no tiene sentido y además desgasta la memoria; ahí solo el TRIM importa.

fsck / chkdsk: el "médico del FS". Detectan bloques corruptos y metadatos inconsistentes. Se corren con la partición desmontada (en Linux) o al arrancar (Windows). Ignorarlos tras un corte puede dejar el disco ilegible.

BitLocker y cifrado. Protege el contenido si roban el equipo; pero ojo: si se pierde la clave de recuperación, los datos se pierden también. El cifrado exige copia de la clave aparte.

Revisión didáctica

  • "Desfragmentar el SSD" es un error. No mejora nada y desgasta; en SSD se usa TRIM, no desfragmentación.
  • LVM no es "mágica infinita". Puedes crecer un LV si hay espacio en el VG; si el disco físico está lleno, no hay de dónde sacar. Tiene límites reales.
  • fsck en una partición montada es peligroso. Se corre desmontada; hacerlo en uso puede corromper más. En Windows, chkdsk se agenda para el reinicio.
  • BitLocker no sustituye la copia. Cifra, pero si se pierde la clave, fin; y no protege contra borrado. Sigue haciendo backup.
  • fdisk (MBR) no ve discos GPT grandes. Para >2 TB usa gdisk/parted. Mezclar herramienta y tabla da líos.

Hilo de aprendizaje sugerido: (1) disco → partición (fdisk/gparted) → (2) volúmenes lógicos LVM (PV/VG/LV) → (3) desfragmentación (HDD vs SSD) → (4) fsck/chkdsk como medicina del FS → (5) cifrado BitLocker y su riesgo de clave → (6) cuándo usar cada herramienta.
