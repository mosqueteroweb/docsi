Configuración de usuarios y grupos locales

En cualquier sistema multiusuario, la gestión de cuentas es la base de la seguridad y del trabajo colaborativo. Un usuario es la identidad con la que una persona o un proceso accede al sistema; un grupo es una colección de usuarios a la que se le pueden asignar permisos de forma conjunta. Tanto en GNU/Linux como en Windows existen herramientas de línea de comandos y gráficas para crear, modificar y eliminar cuentas.

1. Usuarios y grupos locales

  • Cuenta de usuario: identidad con nombre, contraseña y directorio personal (home).
  • Cuenta de sistema: creada por el SO para que un servicio (p.ej. www-data, nobody) funcione aislado.
  • Grupos primario y suplementarios: cada usuario tiene un grupo primario y puede pertenecer a varios grupos adicionales.
  • Administrador/root: en Linux el superusuario root (UID 0) lo controla todo; en Windows es el grupo Administradores.

2. Identificadores UID y GID

El sistema no trabaja con nombres sino con números. Cada usuario recibe un UID (User ID) y cada grupo un GID (Group ID). Los permisos de los archivos se registran por UID/GID, no por nombre, por lo que renombrar una cuenta sin cambiar su UID puede causar incoherencias.

Rango UID (Linux)Significado
0Superusuario root
1–999Usuarios/servicios de sistema
1000+Usuarios humanos (normales)

3. Gestión por línea de comandos en Linux

Los archivos maestros son /etc/passwd (cuentas), /etc/shadow (contraseñas cifradas) y /etc/group (grupos).

sudo useradd -m -s /bin/bash -G desarrollo ana   # crea usuario ana, lo mete en el grupo desarrollo
sudo groupadd ventas                        # crea el grupo ventas
sudo usermod -aG ventas ana                  # añade ana al grupo ventas (conserva los demás)
sudo passwd ana                             # fija/ cambia la contraseña de ana
sudo userdel -r ana                          # elimina la cuenta y su home

4. Gestión por línea de comandos en Windows

En Windows los comandos equivalentes son net user y net localgroup; en versiones modernas también existe New-LocalUser de PowerShell.

net user ana /add /passwordreq:yes            # crea usuario local ana
net localgroup ventas /add                    # crea el grupo local ventas
net localgroup ventas ana /add                # añade ana al grupo ventas
net user ana /delete                          # elimina la cuenta

5. Gestión mediante interfaz gráfica (GUI)

  • Linux (GNOME/KDE): Ajustes → Usuarios, o la herramienta users-admin.
  • Windows: lusrmgr.msc (Usuarios y grupos locales) o Configuración → Cuentas → Otras personas.
  • La GUI escriben en los mismos archivos/archivo de seguridad que la línea de comandos, por lo que ambos métodos son equivalentes.

Ejemplo resuelto en clase

Caso práctico: Crear un usuario y añadirlo a un grupo.

  1. Abre 'Usuarios y grupos' (Linux: useradd -m ana; Windows: cuenta local).
  2. Crea el grupo 'profes' y añade a ana: usermod -aG profes ana.
  3. Verifica con groups ana que pertenece a profes.
  4. Explica que los grupos sirven para aplicar permisos a varios usuarios a la vez.

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • Usuario = "el carné"; grupo = "el equipo". El usuario es la persona (o proceso) que accede; el grupo es una etiqueta que agrupa varios para darles los mismos permisos de golpe.
  • El sistema no lee nombres, lee números. Por dentro usa UID/GID; el nombre es solo decoración. Por eso renombrar sin cuidado rompe la coherencia.
  • Cuenta de sistema ≠ cuenta de persona. www-data o nobody existen para que un servicio corra aislado; no son para que un humano inicie sesión.

Para profundizar en los contenidos actuales

Archivos que lo definen (Linux). /etc/passwd tiene UID, home y shell; /etc/shadow guarda el hash de la contraseña (solo root); /etc/group lista grupos y sus miembros. La CLI y la GUI escriben ahí, por eso son equivalentes.

UID 0 = root. Cualquier cuenta con UID 0 es superusuario; por eso no se juega con los UID. Los usuarios normales empiezan en 1000+. Un proceso con UID 0 puede hacerlo todo: de ahí la regla "no trabajes como root".

Grupo primario vs suplementarios. El primario es el grupo por defecto de sus archivos nuevos; los suplementarios dan permisos adicionales sin cambiar el dueño. usermod -aG añade sin quitar los demás.

Windows: SAM y Administradores. La base de datos de cuentas locales (SAM) guarda los hashes; el grupo Administradores equivale al root de Linux. net user y lusrmgr.msc son las vías.

Por qué importa en un aula. Crear un alumno por puesto, meterlos en el grupo alumnos y limitar su acceso al home evita que toquen la configuración del profe. La gestión de cuentas es la primera línea de seguridad.

Revisión didáctica

  • "Renombrar" no es "cambiar identidad". Si cambias el nombre pero no el UID, el sistema sigue viendo al mismo número; y si reusas un UID, heredas permisos ajenos.
  • root no es "el usuario admin normal". Es UID 0 con control total; usar la sesión de root para tareas cotidianas es un riesgo. Se usa sudo puntual.
  • userdel sin -r deja el home. Borra la cuenta pero no su carpeta personal; eso acumula basura o, peor, conflictos de UID al crear otro usuario.
  • Grupo primario y suplementario no son lo mismo. El primario define el grupo de sus archivos nuevos; los suplementarios solo añaden permisos. Confundirlos da permisos mal configurados.
  • Windows no tiene "root" con ese nombre. Su equivalente es el grupo Administradores; la lógica de privilegio es parecida pero el término distinto.

Hilo de aprendizaje sugerido: (1) usuario vs grupo (persona vs equipo) → (2) UID/GID: el sistema usa números → (3) archivos passwd/shadow/group → (4) root/UID 0 y Administradores → (5) primario vs suplementario → (6) gestión en aula (crear, limitar, borrar con -r).
