Servicios y procesos

Un proceso es un programa en ejecución; un servicio (o demonio) es un proceso en segundo plano que ofrece una funcionalidad continua (impresión, red, web). Administrarlos bien es clave para que el sistema funcione de forma fiable y segura.

1. Servicios con systemd (Linux)

En las distribuciones actuales, systemd es el sistema de init que arranca y gestiona servicios mediante unidades (unit files). Cada servicio se controla con systemctl.

sudo systemctl start nginx        # arranca el servicio
sudo systemctl stop nginx         # lo detiene
sudo systemctl enable nginx        # arranca solo al iniciar el SO
sudo systemctl status nginx        # muestra estado y últimos logs
sudo systemctl restart nginx       # reinicia tras un cambio de configuración

2. Procesos: identificación y control

  • Cada proceso tiene un PID (identificador).
  • ps aux lista los procesos en ejecución.
  • top / htop muestran consumo de CPU y memoria en vivo.
  • kill -TERM PID o kill -9 PID terminan un proceso.
  • La prioridad (nice) ajusta cuánta CPU recibe; renice la cambia en caliente.

3. Planificación de tareas

La automatización permite ejecutar comandos en momentos concretos. En Linux se usa cron (repetitivo) y at (una vez); en Windows, el Programador de tareas.

# Backup cada domingo a las 3:00
0 3 * * 0 tar -czf /backup/etc.tar.gz /etc
# Ejecutar una vez mañana a las 22:30
echo 'tar -czf /tmp/a.tar.gz /home' | at 22:30

4. Monitorización básica

  • systemctl status indica si un servicio está activo, fallido o inactivo.
  • journalctl -u nginx muestra los registros de un servicio concreto.
  • Comprobar la carga del sistema con uptime o htop.

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • Programa parado vs en marcha = "receta vs platillo". El programa en disco es la receta; el proceso es la receta siendo cocinada (con su horno y sus ingredientes). Varios procesos pueden salir del mismo programa.
  • Servicio = "el camarero invisible". Corre en segundo plano sin que nadie lo vea, atendiendo peticiones (imprimir, servir web). No es para que un humano lo use directamente.
  • systemd es "el maestro de ceremonias". Al arrancar, levanta los servicios en orden; si uno falla, puedes ver por qué con status.

Para profundizar en los contenidos actuales

PID y el árbol de procesos. Cada proceso tiene un PID; el primero (PID 1) es systemd, padre de casi todos. ps aux lista; top/htop muestra consumo vivo. Matar un proceso hijo puede tirar el padre.

systemctl: start/stop/enable/status. start lo arranca ahora; enable lo deja listo para el próximo arranque; status dice activo/fallido y muestra los últimos logs. Es la forma moderna de gestionar servicios en Linux.

kill vs kill -9. kill -TERM pide al proceso que termine limpio (guarda datos); kill -9 lo mata a tiros sin limpiar. Usa -9 solo si el -TERM no responde; puede dejar archivos corruptos.

Planificación: cron (repetitivo) vs at (una vez). cron dispara cada semana a las 3:00; at 22:30 dispara una sola vez. Windows usa el Programador de tareas para ambos.

Monitorización: journalctl y uptime. journalctl -u nginx aisla los logs de un servicio; uptime dice cuánto lleva encendido y la carga. Sin monitorizar, no sabes si un servicio cayó.

Revisión didáctica

  • Programa ≠ proceso. El programa es el archivo en disco; el proceso es la instancia en ejecución. Confundirlos lleva a creer que "borrar el programa mata el proceso".
  • start no es "enable". start arranca ahora; si no haces enable, tras reiniciar no vuelve solo. Error típico: "lo arranqué y al día siguiente no estaba".
  • kill -9 no es la primera opción. Mata sin limpiar y puede dejar datos a medias; usa -TERM primero. -9 es la última ratio.
  • Matar un proceso hijo puede tirar el padre. Si matas el hijo de un servicio, el servicio puede caer. Hay que saber el árbol (pstree) antes de matar.
  • cron no es "at". cron es cíclico (cada domingo); at es puntual (una vez). Mezclarlos programa la tarea mal.

Hilo de aprendizaje sugerido: (1) programa vs proceso vs servicio → (2) PID y árbol (ps/top) → (3) systemctl (start/enable/status) → (4) kill vs kill -9 → (5) cron vs at → (6) monitorizar con journalctl/uptime.
