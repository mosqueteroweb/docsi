Comandos de sistemas operativos libres y propietarios

Administrar un sistema exige conocer la línea de comandos. Aunque GNU/Linux y Windows son entornos distintos, muchas tareas tienen comandos equivalentes. Dominar ambos facilita la interoperabilidad y el trabajo en entornos mixtos.

2. Gestión de usuarios y permisos

  • Linux: useradd, usermod, chmod, chown.
  • Windows: net user, net localgroup, icacls, o cmdlets de PowerShell New-LocalUser.
  • En PowerShell muchos comandos de Linux tienen alias (p.ej. ls → Get-ChildItem).

3. Red y sistema

# Linux
ip addr show          # configuración de red
systemctl status sshd  # estado de un servicio
# Windows
ipconfig /all         # configuración de red
sc query sshd          # estado de un servicio

4. PowerShell vs bash

  • bash (Linux) es un intérprete clásico basado en texto con tuberías (pipes).
  • PowerShell (Windows) maneja objetos, no solo texto, y usa verbos (Get-, Set-, New-).
  • Ambos permiten scripts de automatización y acceso remoto.

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • La línea de comandos es "hablarle directo al sistema". La GUI es el menú; la CLI es dictar la orden. Más rápida para repetir y para gestionar a distancia.
  • Linux y Windows son "dos idiomas distintos". Hacen lo mismo (copiar, mover) pero con palabras distintas (cp vs copy). Saber el par equivale a ser bilingüe.
  • bash vs PowerShell: texto vs objetos. bash pasa texto por tuberías; PowerShell pasa objetos. Por eso un pipe de PowerShell conserva propiedades, no solo líneas.

Para profundizar en los contenidos actuales

Equivalencias básicas. ls↔dir, cp↔copy, mv↔move, rm↔del. Pero ojo: rm -r borra carpetas; en Windows rmdir /s. El peligro es igual de real en ambos.

Gestión de usuarios/permisos por CLI. Linux: useradd/chmod; Windows: net user/icacls. Lo mismo que la GUI pero scripteable y repetible en 50 equipos.

Red y servicios. ip addr↔ipconfig /all; systemctl status↔sc query. Diagnosticar conexión o servicio caído se hace por CLI en los dos sistemas.

Pipes y filtros. En bash, | grep filtra salida; en PowerShell, | Where-Object. La idea (encadenar comandos) es igual; la sintaxis cambia.

Por qué importa en el aula. Un técnico de FP se encontrará Windows y Linux; dominar ambos comandos lee errores, despliega y documenta sin depender de la GUI. Es la base de la automatización.

Revisión didáctica

  • "El comando es igual en los dos" es falso. cp y copy parecen lo mismo pero su sintaxis y opciones difieren; usar una en el otro da error.
  • rm y del no son inocentes. rm -rf o rmdir /s borran sin papelera; un / mal puesto en Linux destruye el sistema. La CLI no pregunta.
  • bash no es "PowerShell con otras palabras". PowerShell maneja objetos; un pipe conserva tipo. Tratarlo como texto plano falla al filtrar.
  • systemctl no es "sc". systemctl es alto nivel (start/enable/status unificado); sc es más básico. Mezclarlos confunde el modelo de cada SO.
  • La GUI hace lo mismo, pero no es repetible. Hacerlo a mano en 50 equipos es lento y error; la CLI se scriptea. Por eso se enseña.

Hilo de aprendizaje sugerido: (1) CLI vs GUI (hablarle directo) → (2) equivalencias Linux↔Windows (cp/copy, ls/dir) → (3) usuarios/permisos por CLI → (4) red/servicios por CLI → (5) pipes (grep vs Where-Object) → (6) riesgos (rm -rf sin papelera).
