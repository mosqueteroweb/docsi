Configuración del protocolo TCP/IP

La configuración de red permite a un equipo comunicarse en una red IP. Incluye la asignación de una dirección IP, la máscara de subred, la puerta de enlace y los servidores DNS, ya sea de forma manual (estática) o automática (DHCP).

1. Dirección IP, máscara y gateway

Una dirección IPv4 (p.ej. 192.168.1.20) identifica al equipo. La máscara (255.255.255.0) delimita la parte de red y la de host. La puerta de enlace (gateway) es la IP del router que sale hacia otras redes.

2. Servidores DNS

El DNS traduce nombres (www.example.com) a direcciones IP. Se configuran normalmente dos: primario y secundario, para redundancia.

3. IPv4 frente a IPv6

IPv4 usa 32 bits y notación decimal punteada; IPv6 usa 128 bits y notación hexadecimal, para resolver la escasez de direcciones.

4. Configuración estática vs DHCP

La estática se introduce manualmente y es fija; DHCP la asigna dinámicamente el servidor con tiempo de concesión (lease).

Caso práctico: Configurar TCP/IP en un equipo.

  1. Abre la configuración de red y elige 'IPv4'.
  2. Introduce IP 192.168.1.10, máscara 255.255.255.0, gateway 192.168.1.1, DNS 8.8.8.8.
  3. Explica que la máscara define la subred y el gateway sale fuera de ella.

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • La IP es "el número de teléfono del equipo". Sin ella, nadie sabe dónde enviar los datos. La máscara dice "qué parte es el prefijo (red) y cuál el número (host)".
  • Gateway = "el operador de cabina". Si quieres hablar con fuera de tu red, pasas por él. Sin gateway, solo hablas con los de tu misma red.
  • DNS = "la agenda de la guía telefónica". Traduce nombres (google.com) a IP; si falla, escribes la IP pero no el nombre. Por eso se ponen dos.

Para profundizar en los contenidos actuales

Máscara y red/host. Con 255.255.255.0 (/24), los 3 primeros octetos son red y el último es host (256 direcciones, 254 utilizables). Cambiar la máscara cambia qué equipos se ven "en la misma red".

Estática vs DHCP. Estática: fija, para servidores/impresoras (siempre en la misma IP); DHCP: el router da IP temporal (lease) a portátiles/móviles. Un servidor con IP que cambia rompe los accesos.

IPv4 vs IPv6. IPv4 (32 bits, ~4.300M direcciones) se agotó; IPv6 (128 bits) da de sobra y usa hexadecimal (2001:db8::). Conviven hoy; el equipo suele tener las dos.

DNS primario y secundario. Si el primario cae, el secundario resuelve. Usar el del router (que a veces falla) o uno público (8.8.8.8, 1.1.1.1) da redundancia real.

netplan en Linux. El ejemplo usa YAML: addresses: [192.168.1.20/24] junta IP y máscara (/24 = 255.255.255.0). Un error de indentación deja la interfaz sin configurar.

Revisión didáctica

  • "Puse la IP pero no navego" suele ser gateway o DNS. Si ves la red local pero no internet, falta gateway; si navegas por IP pero no por nombre, falta/ mal DNS. Hay que separar síntomas.
  • Máscara mal = equipos que "no se ven". Una /24 con IP 192.168.1.x no habla con 192.168.2.x sin router. La máscara define el alcance local; no es decoración.
  • Servidor con DHCP es un error. Si el servidor recibe IP que cambia, los clientes lo pierden. Lo estático es para lo que debe ser siempre alcanzable.
  • /24 no es "255.255.255.0 escrito raro" a veces. /16 = 255.255.0.0 (muchos más hosts). Confundir el prefijo deja la red mal dimensionada.
  • IPv6 no es "IPv4 con más puntos". Es otro protocolo (hex, 128 bits); configurarlo mal deja el equipo sin acceso aunque la IPv4 esté bien.

Hilo de aprendizaje sugerido: (1) IP = teléfono, máscara = prefijo → (2) gateway (salida) y DNS (nombres) → (3) máscara red/host y /24 → (4) estática vs DHCP (cuándo cada una) → (5) IPv4 vs IPv6 → (6) netplan y errores de sintaxis.
