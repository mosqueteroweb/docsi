Ficheros de configuración de red

En sistemas operativos existen ficheros y utilidades para definir la red de forma persistente. En Linux destacan /etc/network/interfaces, Netplan y NetworkManager (nmcli); en Windows, netsh permite configuración por línea de comandos.

1. /etc/network (Debian)

El fichero /etc/network/interfaces define interfaces con 'iface eth0 inet static' o 'dhcp'. Se aplica con ifup/ifdown.

2. Netplan (Ubuntu)

Netplan usa ficheros YAML en /etc/netplan/*.yaml y aplica la configuración con 'netplan apply', generando configuración para NetworkManager o systemd-networkd.

3. nmcli (NetworkManager)

nmcli permite gestionar conexiones sin editar ficheros: 'nmcli con add type ethernet ...'. Es la vía recomendada en muchas distros.

4. netsh en Windows

netsh interface ip set address permite fijar IP, máscara y gateway; netsh interface ip set dns ajusta los servidores DNS.

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • El fichero de config es "la libreta de direcciones del equipo". Dice cómo conectarse al arrancar; sin él, cada reinicio olvida la red. Por eso es persistente.
  • Editar el fichero vs usar el comando = "escribir la receta vs decírsela al cocinero". nmcli/netsh aplican y guardan; tocar el YAML a mano da control fino pero exige sintaxis.
  • Linux tiene varias "libretas" según distro. interfaces (Debian viejo), netplan (Ubuntu), nmcli (muchas). La misma idea, distinta carpeta.

Para profundizar en los contenidos actuales

/etc/network/interfaces. Con iface eth0 inet static fijas IP/máscara/gateway; con dhcp las pide. ifup/ifdown aplican. Simple pero solo una config por interfaz.

Netplan (YAML). En /etc/netplan/*.yaml, la indentación es la sintaxis; netplan apply genera la config real para NetworkManager o systemd-networkd. Un espacio mal puesto rompe todo.

nmcli. nmcli con add type ethernet ... crea una conexión sin tocar ficheros; útil para cambiar entre WiFi/ethernet por script. Es la vía recomendada en portátiles.

netsh en Windows. netsh interface ip set address "Ethernet" static ... fija IP; set dns los DNS. Equivale a la GUI pero repetible y scripteable.

Backend importa. Netplan puede delegar en NetworkManager o systemd-networkd; si editas interfaces a mano pero el backend es otro, el cambio no surte efecto. Hay que saber quién manda.

Revisión didáctica

  • "Edité interfaces pero no cambia nada" = backend distinto. Si la distro usa Netplan/NetworkManager, tocar interfaces a mano no aplica. Hay que usar la herramienta que manda.
  • YAML no perdona la indentación. Un espacio de más en netplan deja la interfaz sin red. No es "bonito", es sintaxis estricta.
  • nmcli add no es "modificar lo existente". Crea una conexión nueva; si ya había una, pueden solaparse. Hay que con mod o borrar la vieja.
  • netsh pide el nombre exacto de la interfaz. "Ethernet" debe coincidir con el del sistema; si se llama "Ethernet 2", el comando falla. netsh int show int lo confirma.
  • Configurar sin probar es "conducir a ciegas". Tras netplan apply o netsh, hay que ip a/ipconfig para ver la IP real. No dar por hecho.

Hilo de aprendizaje sugerido: (1) fichero = config persistente → (2) interfaces (Debian) → (3) netplan YAML y su backend → (4) nmcli (con add/mod) → (5) netsh en Windows → (6) errores típicos (indentación, nombre de interfaz, backend).
