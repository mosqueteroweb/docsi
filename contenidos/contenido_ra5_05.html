Herramientas gráficas y comandos

La administración de red se realiza tanto por línea de comandos como por interfaces gráficas. Conocer ambas facilita la resolución de incidencias en Linux y Windows.

1. Línea de comandos en Linux

ip, nmcli, ss, ping, dig, traceroute permiten inspeccionar y modificar la configuración.

2. Interfaces gráficas en Linux

NetworkManager (applet), nmtui (texto) y entornos como GNOME Settings ofrecen configuración visual.

3. Línea de comandos en Windows

netsh, ipconfig, ping, tracert, Get-NetIPConfiguration (PowerShell).

4. Interfaces gráficas en Windows

Centro de redes y recursos compartidos, y la app Configuración > Red e Internet.

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • GUI y CLI son "el mismo destino por dos caminos". La GUI es cómoda para lo de cada día; la CLI permite repetir, automatizar y acceder remoto. Un técnico usa ambas.
  • nmtui = "la GUI en modo texto". Para servidores sin escritorio, da menús visuales por terminal. Lo mejor de los dos mundos cuando no hay ratón.
  • ncpa.cpl = "el panel de conexiones de Windows". Abre el Centro de redes para ver adaptadores y cambiar IP a golpe de clic. Equivale a netsh pero visual.

Para profundizar en los contenidos actuales

Linux CLI. ip link show lista interfaces; nmcli device status su estado; ss/dig/ping para diagnóstico. Repetible y scripteable en muchos equipos.

Linux GUI. El applet de NetworkManager, nmtui (texto) y GNOME Settings. Para aula con escritorio, la GUI basta; para servidor, nmtui o CLI.

Windows CLI. netsh, ipconfig, tracert, y Get-NetIPConfiguration (PowerShell, devuelve objetos). La CLI de Windows es potente para scripts de despliegue.

Windows GUI. Centro de redes y recursos compartidos y Configuración → Red. ncpa.cpl abre directo el panel de adaptadores. Cómodo para el alumno que empieza.

Por qué enseñar las dos. En un aula te encontrarás equipos con y sin escritorio; el examen FP pide ambas. Saber pasar de GUI a CLI (y viceversa) es la competencia real.

Revisión didáctica

  • "Solo sé la GUI" es insuficiente en FP. El examen y los servidores exigen CLI; además, la GUI no se scriptea para 30 equipos. Hay que dominar ambas.
  • nmtui no es "una GUI gráfica". Es texto por terminal (sin escritorio); confundirlo con GNOME Settings lleva a buscar un ratón donde no lo hay.
  • ipconfig no es "ip en Windows". ipconfig (Windows) y ip (Linux) son distintos comandos; usar uno en el otro da error. Hay que saber el par.
  • Get-NetIPConfiguration no es "ipconfig con otra cara". Devuelve objetos que se filtran en PowerShell; tratarlo como texto plano pierde su potencia.
  • La GUI y la CLI pueden desincronizarse. Si cambias por CLI y la GUI no refresca, ves datos viejos. Hay que reabrir o usar la misma herramienta para confirmar.

Hilo de aprendizaje sugerido: (1) GUI vs CLI (mismo destino) → (2) Linux CLI (ip/nmcli/ss) y GUI (nmtui/GNOME) → (3) Windows CLI (netsh/ipconfig/Get-NetIP) y GUI (ncpa.cpl) → (4) nmtui = texto sin escritorio → (5) por qué enseñar ambas en FP → (6) errores (desincronización, nombres distintos).
