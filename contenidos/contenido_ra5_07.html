Protocolos TCP/IP

La familia TCP/IP es el conjunto de protocolos de Internet. Se organiza en un modelo de 4 capas; cada capa ofrece servicios a la superior. Contrasta con el modelo OSI de 7 capas.

1. Modelo TCP/IP vs OSI

TCP/IP: Enlace, Red, Transporte, Aplicación. OSI añade Física, Sesión y Presentación como capas separadas.

2. TCP y UDP

TCP fiable y orientado a conexión; UDP rápido y sin conexión.

3. ICMP y ARP

ICMP para diagnóstico (ping); ARP resuelve IP a MAC dentro de la LAN.

4. DHCP y DNS

DHCP asigna direcciones automáticamente; DNS traduce nombres a IP.

Caso práctico: Explicar los protocolos TCP/IP.

  1. TCP es orientado a conexión (fiable, ej. web); UDP es sin conexión (rápido, ej. vídeo).
  2. IP entrega paquetes; TCP los ordena y confirma recepción.
  3. DNS traduce nombre→IP; HTTP sirve páginas; HTTPS las cifra con TLS.
  4. Dibuja la pila: Aplicación → Transporte (TCP/UDP) → Red (IP) → Enlace.

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • El modelo de capas es "una cadena de montaje". Cada capa hace su parte (empaquetar, enrutar, entregar) y se la pasa a la siguiente. El dato baja por capas al enviar y sube al recibir.
  • TCP/IP vs OSI = "lo que se usa vs lo que se estudia". Internet usa TCP/IP (4 capas); OSI (7) es el modelo teórico para entender. En FP se citan las dos, pero la real es TCP/IP.
  • ARP = "el servicio de recepción de la LAN". Sabe qué MAC tiene cada IP dentro de tu red local; sin ARP, el paquete no sale del equipo hacia el switch.

Para profundizar en los contenidos actuales

Las 4 capas TCP/IP. Aplicación (HTTP/DNS/DHCP), Transporte (TCP/UDP), Red (IP/ICMP/ARP), Enlace (Ethernet/Wi-Fi). Cada una entrega a la de abajo; por eso un "paquete" se llama segmento (TCP), datagrama (IP) o trama (Ethernet) según la capa.

TCP vs UDP (repaso). TCP fiable (retransmite lo perdido, ordena); UDP ligero (sin confirmación). DNS usa UDP para rapidez; HTTP usa TCP para que la página llegue entera.

ICMP y ARP. ICMP para diagnóstico (ping, tracert); ARP resuelve IP→MAC en la LAN. Fuera de tu red, quien entrega es el router (gateway), no ARP.

DHCP y DNS. DHCP da la IP automática (al arrancar); DNS traduce nombres a IP (al navegar). Sin DHCP, tendrías que poner IP a mano; sin DNS, navegarías por número.

Encapsulado. Los datos de tu app se meten en un segmento TCP, que se mete en un datagrama IP, que se mete en una trama Ethernet. Como muñecas rusas. Al recibir, se van quitando capas.

Revisión didáctica

  • "OSI es el modelo real" es un error. Internet funciona con TCP/IP (4 capas); OSI es teórico. Estudiar OSI ayuda, pero no confundas "lo que se examina" con "lo que usa el router".
  • ARP no cruza el router. Solo resuelve IP→MAC dentro de la LAN; para fuera de tu red, el destino es la MAC del gateway. Pensar que ARP "encuentra Google" es falso.
  • DNS no es "parte de TCP". Usa UDP (o TCP en respuestas grandes); es de capa de aplicación, no de transporte. Mezclar capas rompe el modelo.
  • Los nombres de "paquete" dependen de la capa. Segmento (TCP), datagrama (IP), trama (Ethernet). Llamar "paquete" a todo vale coloquialmente, pero en examen conviene precisar.
  • DHCP y DNS no son lo mismo. DHCP da tu IP al arrancar; DNS traduce nombres al navegar. Uno es "dar dirección", otro "traducir nombre".

Hilo de aprendizaje sugerido: (1) modelo de capas = cadena de montaje → (2) TCP/IP (4) vs OSI (7) → (3) capas y sus protocolos → (4) TCP/UDP, ICMP, ARP → (5) DHCP/DNS → (6) encapsulado y errores típicos (ARP no cruza router, DNS no es TCP).
