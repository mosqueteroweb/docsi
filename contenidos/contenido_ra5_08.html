Configuración de adaptadores de red

El adaptador de red (NIC) es el hardware que conecta el equipo a la red. Requiere driver y configuración. Puede ser Ethernet (cable) o Wi-Fi inalámbrico, en Linux o Windows.

1. NIC y drivers

La tarjeta nece sita un driver que el SO cargue. En Linux suele ser de código abierto; en Windows se instala vía el fabricante.

2. Ethernet (cable)

Conecta por RJ-45 a un switch. Configuración vía DHCP o estática; se verifica con 'ip link'.

3. Wi-Fi (inalámbrico)

Se asocia a un punto de acceso (AP) con SSID y contraseña; en Linux con nmcli/wpa_supplicant.

4. Verificación en SO

Linux: 'ip link', 'lspci'. Windows: Administrador de dispositivos (devmgmt.msc).

Ampliación de contenido

Para entender lo anterior (puentes conceptuales)

  • El adaptador es "la boca y el oído del equipo". Sin NIC (física o USB), el equipo no habla con nadie. El driver es el traductor que le dice al SO cómo usarla.
  • Ethernet vs Wi-Fi = "cable fijo vs radio". El cable es estable y rápido; el Wi-Fi da movilidad pero depende de cobertura y clave. Mismo resultado (IP), distinto medio.
  • Sin driver, la tarjeta es "muda". El SO la ve pero no sabe hablarle; de ahí que a veces "la tarjeta está pero no conecta".

Para profundizar en los contenidos actuales

NIC y drivers. lspci | grep -i network (Linux) dice qué tarjeta hay; el driver correcto la hace funcionar. En Windows, devmgmt.msc muestra si el driver está bien (sin triángulo amarillo).

Ethernet. Cable RJ-45 a un switch; el estándar suele ser Gigabit (1000 Mbps). ip link muestra si la interfaz está UP y si negoció velocidad. Un cable malo deja el enlace DOWN.

Wi-Fi. Se asocia a un AP con SSID y clave (WPA2/WPA3). En Linux, nmcli dev wifi connect SSID password clave o wpa_supplicant. El 2.4 GHz llega más lejos; el 5 GHz es más rápido pero corto de alcance.

Verificación. Antes de tocar IP, hay que ver que el adaptador tiene enlace (LED, ip link UP). Configurar TCP/IP sobre una NIC sin enlace es inútil.

USB tether / móvil. Comparte la 4G/5G del móvil como adaptador de red; el SO lo ve como una NIC más y le da IP por DHCP. Útil como respaldo de conectividad en el aula.

Revisión didáctica

  • "La IP está bien pero no hay red" suele ser enlace caído. Si ip link dice DOWN, el cable o el driver fallan; la configuración IP da igual. Hay que subir la interfaz primero.
  • Wi-Fi 5 GHz no es "mejor siempre". Es más rápido pero su alcance es corto y se muere con paredes; a 20 m con obstáculos, 2.4 GHz aguanta mejor. Elegir según distancia.
  • Driver mal = tarjeta invisible. En Windows, triángulo amarillo en devmgmt; en Linux, la interfaz ni aparece. "No conecta" puede ser falta de driver, no de red.
  • El SSID es "el nombre", no la clave. Conectar al SSID correcto con clave mala falla; confundir uno con otro da "contraseña incorrecta" aunque la red esté ahí.
  • USB tether no es "Wi-Fi". Usa el móvil como módem por cable/USB; consume datos del móvil. No es un sustituto del router del aula, es un respaldo.

Hilo de aprendizaje sugerido: (1) NIC = boca/oido, driver = traductor → (2) Ethernet (RJ-45, ip link UP) → (3) Wi-Fi (SSID+clave, 2.4 vs 5 GHz) → (4) verificar enlace antes de IP → (5) USB tether → (6) errores (enlace DOWN, driver, SSID vs clave).
